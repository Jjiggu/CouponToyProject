# 9단계 장애 실험 원본 (2026-10-20, Mac)

조건
- 발행자(`local`, 18080)와 적재기(`wb-loader`, 18081) 프로세스, 같은 jar. MySQL 은 `coupon-toy-mysql`(실험 스키마), Redis 는 **임시 컨테이너** `redis:7.2-alpine`(포트 16379, db 2). 사용자 데이터가 있는 `coupon-toy-redis` 는 쓰지 않았다
- k6 `METHOD=REDIS_WRITE_BEHIND SCENARIO=smoke RATE=200 DURATION=15s MEMBERS=3000 TOTAL_COUNT=1000 WARMUP=0` (회원마다 한 번, 마지막 1건만 같은 회원이 두 번)
- Redis 예약이 300 명을 넘으면 죽였다. Redis 는 `docker kill -s KILL` 뒤 바로 `docker start`, 적재기는 `kill -9` 뒤 2초 쉬고 새 프로세스
- 끝난 뒤 DB 발급 행이 3초 동안 늘지 않을 때 결과 API 와 대사 API 를 불렀다
- 실행 스크립트: `build/lab-tmp/exp9-loss.sh` (저장소 밖)

| 죽인 것 | Redis 설정 | 죽일 때 Redis 예약 / DB 행 (거의 같은 시점) | Redis 재시작 직후 예약 | 접수(202) / 거절(409) | DB 발급 행 | Redis 예약 | 대사: DB 에만 있는 회원, issued_count | 5xx |
|---|---|---|---:|---|---:|---:|---|---:|
| Redis | `--appendonly no --save ""` | 368 / 400 | 0 | 1411 / 1564 | 1408 | 1000 | 408, 1408 (재고 1000) | 0 |
| Redis | `--appendonly yes --appendfsync everysec` | 363 / 378 | 499 | 1000 / 2001 | 1000 | 1000 | 0, 1000 | 0 |
| 적재기 | `--appendonly yes --appendfsync everysec` | 387 / 415 | - | 1000 / 2001 | 1000 | 1000 | 0, 1000 | 0 |

- "죽일 때" 두 값은 Redis 를 먼저, DB 를 나중에 읽어 그 사이 적재된 만큼 DB 가 크다
- 영속화를 끈 경우 k6 가 못 보낸 요청 26 건(그 밖에는 0). 대사가 Redis 에서 채운 회원은 세 경우 모두 0
- Redis 재시작 직후 예약은 재시작을 확인한 뒤 바로 읽은 값이라, 재시작 뒤 들어온 요청이 섞여 있다(everysec 499)
