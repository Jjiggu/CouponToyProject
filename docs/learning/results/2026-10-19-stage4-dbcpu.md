# 4단계 MySQL CPU 실행 원본 (2026-10-19): 동기 Lua 와 비동기의 DB 쓰기 부하

질문: 비동기로 바꿔도 발급 이력 쓰기(INSERT, 조건부 UPDATE, COMMIT)가 많아지면 DB CPU 부하가 생기는가?

실행 조건
- 앱·k6 는 [k6 원본](2026-10-19-stage4-k6.md) 과 같다. k6 `SCENARIO=burst VUS=100 WARMUP=200`, `TOTAL_COUNT = MEMBERS = ITERATIONS` 를 1000, 5000 으로. 앱 하나로 1000 → 5000 순서, 회차마다 `REDIS_LUA`·`REDIS_ASYNC` 를 번갈아 2회씩. 그 뒤 작업 스레드 10 으로 다시 띄워 5000 비동기 2회
- MySQL 8.0.36 컨테이너 CPU 제한 1코어(`cpus: "1.0"`), `innodb_flush_log_at_trx_commit=1`, `sync_binlog=1`, `log_bin=ON`
- 컨테이너 CPU: Docker API(`/containers/coupon-toy-mysql/stats?one-shot=true`)의 누적 CPU 를 0.1초 간격으로 기록(컨테이너 안에 프로세스를 띄우지 않음). 확정 구간 = 측정 쿠폰 생성 시각(`coupons.created_at`)부터 k6 가 잰 "확정까지" 시각. 100% = 1코어
- 문장별 CPU: `performance_schema.events_statements_summary_by_digest` 의 `SUM_CPU_TIME` 을 실행 전후로 빼서 구했다. 이 값은 수집 항목 `events_statements_cpu` 가 켜져 있어야 쌓이므로 실험 동안만 켰다가 끝나고 껐다(기본값 NO). 실행 전체(회원 준비, 워밍업 200건, 결과 조회 포함)를 센다
- 확정 구간 CPU 에는 k6 teardown 의 결과 API 조회(50ms 간격)와 InnoDB 백그라운드 스레드 CPU 도 들어 있다
- 실행 스크립트: `build/lab-tmp/exp4-dbcpu.sh`, 요약: `build/lab-tmp/dbcpu_report.py` (저장소 밖)
