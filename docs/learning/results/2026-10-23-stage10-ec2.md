# 10단계 EC2 측정 원본 (2026-10-23 15:07 ~ 16:15)

실행 조건
- 8·9단계와 같은 인스턴스 구성(db c7g.large, app c7g.xlarge, k6 c7g.large, 같은 서브넷). 인스턴스를 중지했다 다시 켠 뒤라 물리 서버가 9단계 측정(2026-10-21) 때와 다를 수 있다. 그래서 9단계도 이날 다시 쟀다
- MySQL 8.0.36 (1 CPU / 1GB, 커밋 동기화 1/1), Redis 7.2 (1 CPU / 1GB, 영속화 끔)
- 9단계 `wb`(REDIS_WRITE_BEHIND, 회원 확인 `existsById`)와 10단계 `wb10`(REDIS_WRITE_BEHIND_NO_TX, 회원 확인 `MemberExistsRepository.countByMemberId`, SUPPORTS). 둘 다 같은 적재기(wb-loader, 스레드 1개, 묶음 최대 100)
- 표본의 발급 수는 발급 행 수, 정합성 칸은 대사 전이라 "issued_count = 행 수" 검사를 빼고 본 것이다(9단계와 같음). 판정 조건도 8·9단계와 같다
- "확정까지" 시간은 발급이 10만 건을 넘으면 결과 API(`LabService.result`)가 느려져(명단 비교에 List.contains) 실제 적재보다 길게 잡힌다. 정상 구간 적재 TPS 는 DB 에서 따로 1초마다 세므로 영향이 없다
