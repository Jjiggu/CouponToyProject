# 3단계 바꿔본 조건 실행 원본 (2026-10-19): WATCH 재시도 상한, Lettuce 커넥션 풀, Redis I/O 스레드, Redis 영속화

[3단계 문서](../03-redis-transaction-lua.md) 3절에서 "실행 안 함" 이었던 조건을 실행한 기록이다. 해석은 문서 4-8 에 있다.

공통 실행 조건 (2026-10-17 과 같은 환경)
- 앱: macOS 호스트에서 `./gradlew bootRun` (OpenJDK 17.0.19, 8 cores), 포트 18080, 프로필 local, `CouponToyProject_lab` 스키마, Redis db 2, SQL 로그 끔. Tomcat 200, Hikari 10
- MySQL 8.0.36 (Docker 1 CPU / 1GB), Redis 7.2.13 (`redis:7.2-alpine`)
- k6 공통: `MEMBERS=1000 VUS=100 ITERATIONS=1000 WARMUP=200 SCENARIO=burst`. 재고는 `TOTAL_COUNT` (100 또는 1000)
- **실행마다 호스트의 TIME_WAIT 연결이 100개 아래로 빠질 때까지 기다린 뒤 시작했다.** 첫 시도(대기 없이 연속 실행)에서 WATCH 최대 30·100 의 2·3회차가 연결 실패로 망가졌기 때문이다(아래 "첫 시도"). macOS: `net.inet.tcp.msl=15000`(TIME_WAIT 30초), 임시 포트 `49152~65535`(16384개)
- 새 Redis 연결 = 실행 전후 `INFO stats` 의 `total_connections_received` 차이(측정용 redis-cli 1개 제외, 워밍업 200건 포함). TIME_WAIT 최대 = 실행 중 0.5초마다 `netstat -an -p tcp` 로 센 TIME_WAIT 수의 최대값, 괄호는 그중 Redis 포트로 가는 연결(WATCH 재시도 상한 실행은 나눠 세지 않았다)
- k6 종료 코드 99 는 기준값(`coupon_issue_http_duration p(95)<500` 등)을 넘은 것이다. 측정은 끝까지 했다
- JUnit 은 `./gradlew test --tests '*RedisReservationTest.concurrentRequests'`(풀 실험은 클래스 전체) 가 `build/lab/stage3-redis.md` 에 남긴 표를 옮겼다. 요청 50, 스레드 50, Hikari 10, 테스트 DB `CouponToyProject_test`, Redis db 1

조건별 실행 방법
| 조건 | 바꾼 것 | 순서 |
|---|---|---|
| WATCH 재시도 상한 | 앱·테스트 환경변수 `COUPON_ISSUE_REDIS_WATCH_MAX_ATTEMPTS` = 10, 30, 100 | HTTP: 상한마다 앱을 띄워 재고 1000 WATCH 3회. JUnit: 상한마다 1번 실행(1번에 3회차) |
| Lettuce 커넥션 풀 | `build.gradle` 에 `runtimeOnly 'org.apache.commons:commons-pool2'` 를 잠시 추가하고 `SPRING_DATA_REDIS_LETTUCE_POOL_ENABLED=true`. 풀 100개는 `SPRING_DATA_REDIS_LETTUCE_POOL_MAX_ACTIVE=100`, `..._MAX_IDLE=100` 을 더함. 실험 뒤 의존성을 지웠다 | 설정마다 앱을 띄워 회차마다 MULTI/EXEC(재고 100) → WATCH(재고 100) → Lua(재고 100) → WATCH(재고 1000). 풀 100개는 Lua 를 빼고 같은 순서. 풀 없음 → 풀 8개 → 풀 100개 |
| Redis I/O 스레드 | 별도 컨테이너 `docker run -d --name coupon-lab-redis-io -p 6380:6379 --cpus 4 -m 1g redis:7.2-alpine redis-server --appendonly no --save "" --io-threads N --io-threads-do-reads yes`, 앱·테스트는 `SPRING_DATA_REDIS_PORT=6380` | N=1 → N=3. 회차마다 SET 명령만 → MULTI/EXEC → Lua (재고 100), 그 뒤 JUnit 1번 |
| Redis 영속화 | 별도 컨테이너(`-v <빈 디렉터리>:/data --cpus 1 -m 1g`)를 설정만 바꿔 띄움. 앱 없이 `redis-cli` 로 `SET coupon:total:{id} 1000` 과 `SADD coupon:issued:{id} <회원>` 100번을 보낸 직후 재시작 | 설정마다 쿠폰 1 예약 → `docker restart -t 10` → SCARD → 쿠폰 2 예약 → `docker kill -s KILL` → `docker start` → SCARD |

프로젝트의 `coupon-toy-redis` 는 `--appendonly no --save ""` 라 재시작하면 기존 db 0 데이터가 사라진다. 그래서 I/O 스레드와 영속화 실험은 별도 컨테이너에서 했다.
