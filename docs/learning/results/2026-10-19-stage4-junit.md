# 4단계 JUnit 실행 원본 (2026-10-19): @Async 비동기 확정

`./gradlew test --tests '*AsyncIssueTest' --tests '*TransactionalEventListenerTest'` 가 `build/lab/stage4-async.md` 에 남긴 내용을 옮겼다.

실행 조건
- Redis 7.2.13 (Docker, io-threads 1, AOF·RDB 끔), 테스트는 db 1
- MySQL 8.0.36 (Docker, 1 CPU / 1GB), REPEATABLE READ, DB `CouponToyProject_test`
- 테스트 JVM: macOS 호스트, OpenJDK 17.0.19, 8 cores, Hikari 최대 10, Lettuce 기본 설정
- 비동기 스레드 풀: 스레드 4, **큐 50**(포화 재현용으로 줄임, 앱 기본 50000), AbortPolicy. CallerRuns·Discard 는 해당 테스트가 실행 중인 풀의 거부 정책을 잠시 바꾼다
- 동시 요청은 HTTP 없이 `LabService.issue()` 를 스레드에서 직접 호출. 스레드 수 = 요청 수, 래치로 동시에 출발. 확정이 끝날 때까지(`pending` 0) 기다린 뒤 결과를 본다
- 실패 지점(`FailurePoints`)으로 풀 스레드를 DB 확정 직전에 멈추거나 DB 확정을 실패시켰다
- 전체 테스트(124개, 그중 2개는 MySQL 전역 설정 실험이라 기본 실행에서 건너뜀)를 1번, 4단계 테스트를 2번 더 실행했다. 순서 고정 결과는 3번 모두 같았다(CallerRuns 의 응답까지 시간만 28, 6, 6 ms). 아래는 1회차 기록이고, 동시 요청 표는 2·3회차도 붙였다

`TransactionalEventListenerTest` (2개, 3번 모두 통과)
- 트랜잭션 밖에서 발행: `AFTER_COMMIT` 리스너 실행 안 됨, `fallbackExecution = true` 리스너는 발행한 스레드(`Test worker`, 트랜잭션 없음)에서 즉시, `@Async` 리스너는 `coupon-issue-async-N`(트랜잭션 없음)
- 트랜잭션 안에서 발행 후 커밋: 커밋 전에는 아무것도 실행되지 않음. 커밋 뒤 `AFTER_COMMIT`·`fallbackExecution` 리스너가 발행한 스레드에서 실행, 그때 `isActualTransactionActive()` true. `@Async` 리스너는 풀 스레드(트랜잭션 없음)
- 롤백: 세 리스너 모두 실행 안 됨. 실행기에 넘겨진 작업 수가 커밋 건 1건뿐

## 큐 포화: DiscardPolicy (스레드 4, 큐 50)

- 넘친 요청: ACCEPTED (예외 없음). 풀이 모두 빈 뒤: 확정 결과 {SUCCESS=54}, 미완료 1, Redis 에만 있는 회원 1, 그 회원의 DB 발급 행 없음
- 그 회원 재요청: DUPLICATE

## 큐 포화: AbortPolicy (기본값, 스레드 4, 큐 50, 재고 1000)

- 스레드 4개를 DB 확정 직전에 멈추고 50건을 더 보냄 → 큐 50건
- 다음 요청: REJECTED (HTTP 503), 직후 Redis 예약 54건 (거부된 회원 없음)
- 멈춘 스레드를 놓아준 뒤: 요청 결과 {ACCEPTED=54, REJECTED=1}, 확정 결과 {SUCCESS=54}
- 거부된 회원 재요청: ACCEPTED → DB 발급 행 55

## 접수 직후 DB 확정 전 (재고 1)

- 요청 스레드 `Test worker` 에서 접수(ACCEPTED). DB 확정은 `coupon-issue-async-1, 트랜잭션 false` 에서 실행
- 확정 전: 미완료 1, Redis [111], DB 발급 행 0 → 이때 A 재요청 DUPLICATE, B 요청 SOLD_OUT
- 확정 후: 확정 결과 {SUCCESS=1}, DB 발급 행 1

## 큐 포화: CallerRunsPolicy (스레드 4, 큐 50)

- 넘친 요청: ACCEPTED, DB 확정을 `Test worker` 스레드(요청 스레드)가 직접 실행, 응답까지 28 ms, 응답 직후 DB 발급 행 있음 true
- 앞서 큐에 있던 작업은 아직 멈춰 있는데 넘친 요청이 먼저 커밋됐다. 멈춘 스레드를 놓아준 뒤 DB 발급 행 55
