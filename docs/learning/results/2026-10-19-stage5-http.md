# 5단계 HTTP 실행 원본 (2026-10-19): Redis Pub/Sub, 발행자·구독자 별도 프로세스

실행 조건
- 같은 jar(`./gradlew bootJar`)를 프로필만 바꿔 띄웠다. 발행자 `SPRING_PROFILES_ACTIVE=local`(18080), 구독자 `pubsub-consumer`(18081, 두 번째 구독자 18082). 모두 `CouponToyProject_lab`, Redis db 2, SQL 로그 끔. 각 프로세스 Hikari 최대 10, 작업 스레드 4·큐 50000
- MySQL 8.0.36 (Docker 1 CPU / 1GB), Redis 7.2.13 (Docker 1 CPU / 1GB, AOF·RDB 끔), k6 v2.1.0, macOS 호스트 한 대(8 cores)
- k6 공통: `MEMBERS=1000 VUS=100 ITERATIONS=1000 WARMUP=200 SCENARIO=burst`. e1 `TOTAL_COUNT=100`, e2 `TOTAL_COUNT=1000`
- `REDIS_PUBSUB` 은 teardown 에서 `redisOnlyMembers`(Redis 에 예약만 있는 회원)가 0 이 되거나 2초 동안 줄지 않을 때까지 50ms 간격으로 기다린다. "확정까지" 는 마지막으로 줄어든 시각이다. "마지막 응답 시점 미완료" 는 teardown 첫 조회의 `redisOnlyMembers`(비동기는 `pending`)
- 구독자 쪽 실패 건수는 구독자 로그의 `pubsub confirm failed` 줄 수다(성공은 로그를 남기지 않고 DB 발급 행으로 본다)
- 순서: (1) 발행자 + 구독자 1개로 회차마다 e1 → e2, 각각 `REDIS_ASYNC`(4단계, 발행자 프로세스 안에서 확정)와 `REDIS_PUBSUB` 을 번갈아 3회 (2) 구독자 2개로 e2 3회 (3) 구독자를 모두 내리고 e2 1회 (4) 구독자 종료 실험
- 처음 실행에서 구독자 실패 건수를 세는 함수가 bash 산술 오류를 내 (1)·(2) 의 반복문이 중간에 끝났다(각 1회만 실행). 함수를 고쳐 (1)·(2) 를 다시 돌렸고 아래는 다시 돈 결과다. (3)·(4) 는 처음 실행 그대로다
- 실행 스크립트: `build/lab-tmp/exp5-http.sh`, `exp5-http2.sh`, `lab5.sh` (저장소 밖)

## 구독자가 죽은 뒤 Redis 가 언제 구독자에서 빼는가

구독자만 띄우고(발행 없음) 신호를 보낸 뒤 `PUBSUB NUMSUB` 과 `PUBLISH ... probe` 의 돌려받는 수를 50ms 간격으로 봤다(`docker exec` 한 번에 약 0.1초가 걸려 첫 확인이 0.15초).

```
== KILL: 시작 전 NUMSUB 0
구독자 시작 뒤 NUMSUB 1
  신호 후  0.15s: NUMSUB 0, PUBLISH 받은 구독자 0
프로세스 종료 확인: 종료
== TERM: 시작 전 NUMSUB 0
구독자 시작 뒤 NUMSUB 1
  신호 후  0.15s: NUMSUB 0, PUBLISH 받은 구독자 0
프로세스 종료 확인: 종료
```
