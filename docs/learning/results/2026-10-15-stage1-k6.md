# 1단계 k6 HTTP 실행 원본 (2026-10-15)

실행 조건
- 앱: macOS 호스트에서 `./gradlew bootRun` (OpenJDK 17.0.19, 8 cores, CPU 제한 없음), 포트 18080, 프로필 local, SQL 로그 끔
- DB: 별도 스키마 `CouponToyProject_lab` (MySQL 8.0.36 Docker 1 CPU / 1GB), Redis db 2
- Tomcat 스레드 기본 200, Hikari 최대 풀 기본 10
- k6 공통: `MEMBERS=1000 VUS=100 ITERATIONS=1000 WARMUP=200` (워밍업은 별도 쿠폰에 같은 방식으로 200건 순차 전송)
- 실행 순서: e1 RR → e1 SER → e2 SER → e2 RR → e3 RR → e3 SER (한 번씩만 실행)
- HTTP 응답 시간은 k6 `coupon_issue_http_duration`(발급 요청만), 서버 시간은 결과 API `latencyMs`(진입 → 반환, 커밋 포함)
- 처리량 = 결과 API 요청 수 / (setup 종료 → teardown 시작) 시간. 접수 처리량은 응답을 돌려준 모든 요청, 발급 완료 처리량은 SUCCESS 만
