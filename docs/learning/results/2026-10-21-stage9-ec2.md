# 9단계 EC2 측정 원본 (2026-10-20 23:58 ~ 2026-10-21 00:20)

실행 조건
- 8단계와 같은 인스턴스·설정([2026-10-20-tps-ec2.md](2026-10-20-tps-ec2.md)): db c7g.large(MySQL·Redis 각 1 CPU / 1GB, 커밋 동기화 1/1), app c7g.xlarge, k6 c7g.large, 같은 서브넷
- app 인스턴스에 발행자(`local`, 18080)와 적재기(`wb-loader`, 18081, 스레드 1개, 묶음 최대 100건)
- 표본의 발급 수는 `issued_count` 가 아니라 발급 행 수(`SELECT COUNT(*) FROM coupon_issues`)를 1초마다 셌다. write-behind 는 대사 전까지 `issued_count` 를 갱신하지 않는다
- 정합성 칸은 "issued_count = 발급 행 수" 검사를 빼고 본 것이다(대사 전이라 항상 거짓). 나머지(회원당 한 번, 재고 이하, 전량 발급, Redis 예약 = DB 행)는 모두 지켜졌다. 이 측정의 쿠폰들에는 대사를 부르지 않았다(대사는 JUnit 과 Mac HTTP 확인에서 검증)
- 판정은 8단계와 같다(정상 구간 5~28초, 두 회차 모두)
