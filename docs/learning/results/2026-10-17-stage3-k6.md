# 3단계 k6 HTTP 실행 원본 (2026-10-17)

실행 조건 (1·2단계 k6 와 같은 조건)
- 앱: macOS 호스트에서 `./gradlew bootRun` (OpenJDK 17.0.19, 8 cores, CPU 제한 없음), 포트 18080, 프로필 local, SQL 로그 끔
- DB: 별도 스키마 `CouponToyProject_lab` (MySQL 8.0.36 Docker 1 CPU / 1GB), Redis 7.2.13 db 2 (Docker 1 CPU / 1GB, io-threads=1, AOF·RDB 저장 끔)
- Tomcat 스레드 기본 200, Hikari 최대 풀 기본 10, Lettuce 기본 설정(공유 커넥션, 커넥션 풀 없음), WATCH 재시도 최대 10회
- k6 공통: `MEMBERS=1000 VUS=100 ITERATIONS=1000 WARMUP=200` (워밍업은 별도 쿠폰에 같은 방식으로 200건 순차 전송)
- 같은 순서로 3회 반복했다(1회차: e1 LUA → MULTI_EXEC → SET_ONLY → WATCH → PESSIMISTIC, e2 역순, e3 e1 과 같은 순서). PESSIMISTIC 은 같은 세션 기준선
- 일부 실행은 k6 기준값 `coupon_issue_http_duration p(95)<500` 을 넘어 종료 코드 99 로 끝났다(측정은 정상 완료)
- 새 Redis 연결 수는 1회차 실행 전후 `INFO stats` 의 `total_connections_received` 차이다(측정용 redis-cli 연결 제외, 워밍업 200건 포함)
